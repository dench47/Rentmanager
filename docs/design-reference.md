## Общие правила

- Иллюстрации — PNG 5x в `drawable-nodpi` + `FilterQuality.High`;
  мелкие линейные иконки — VectorDrawable (конвертер tools/svg2vd.py, альфы
  обязательны);
- Экспорт иконок из Figma — только по ID инстанса `I<frame>%3B<component>`
  (по компоненту отдаёт мусор: «корона»/«колокол» вместо нужного);
- lineHeight: 15sp→18.2, 13sp→15.7 явно;
- Обновление этого файла обязательно при новых звёздах Вики.

## Каноны экранов (зафиксировано Денисом 2026-09-22)

- **Заголовок экрана всегда нажимаем: тап по названию = тап по стрелке «назад»**
  (вся строка стрелка+название — один кликабельный блок).
- **Тапбар с CTA (низ экрана редактирования)**: панель #EDEDED@90%,
  **верхние углы скруглены 30**, поля 20/10; кнопки СТАТИЧНЫ — клавиатура
  их НЕ поднимает (никакого imePadding на тапбаре), контент скроллится под ней.
- **Баяны по умолчанию ЗАКРЫТЫ** — раскрывает только юзер; шеврон всегда наш
  ic_card_chevron (180° при раскрытии).
- **Паспортные поля в редактировании** — три состояния: пустое (подпись 15/600
  серым в 2 строки, глаз-слэш) / видимое (подпись 13/400 + значение, глаз) /
  скрытое (маска «·· 08»/«······2545», глаз-слэш); глаз переключает видимость.

- **Клавиатура не должна прятать поле ввода** (канон 2026-09-22): `imePadding`
  вешается ТОЛЬКО на скроллящийся контент (вьюпорт сжимается до клавиатуры,
  Compose сам докручивает к полю в фокусе); тапбар с CTA остаётся неподвижным.
- **Числовые поля** (паспорт и т.п.) открывают числовую клавиатуру
  (`KeyboardType.Number`).
- **Пункты меню/шитов всегда рабочие** — «не для красоты написаны»: Сфотографировать
  → TakePicture (FileProvider), Выбрать из галереи → GetContent(image/*),
  Выбрать файл → OpenDocument.

## Автоскролл под клавиатуру: три обязательных условия (исправлено 2026-09-26)

Баг «автоскролл не работает» в «Добавить арендатора» — три причины, все три обязательны:

1. **Триггер — ФОКУС поля, а не ввод.** Доскролл вешался только на `onValueChange`, поэтому
   тап по полю открывал клавиатуру и НИЧЕГО не прокручивал (скролл срабатывал лишь когда
   начинали печатать). Канон: у поля параметр `onFocused` + `.onFocusChanged { if (it.isFocused)
   onFocused() }` (см. `TextValueField` / `PhoneValueField` в AttachTenantScreen, `EditField`
   в TenantEditScreen); вызов из `onValueChange` — только дополнение.
2. **`rootHeightPx` снимать ДО `statusBarsPadding()`.** Если `onGloballyPositioned` стоит после
   паддинга, высота корня меньше окна на статус-бар, а `positionInRoot()` у полей считается от
   полного окна → `keyboardTop = rootHeight - ime` уезжает, `need` занижается, поле не
   докручивается. Правильно: `.fillMaxSize().onGloballyPositioned { rootHeightPx = ... }
   .statusBarsPadding()`.
3. **Контент скролла — `.weight(1f)`**, а не `.fillMaxSize()` (канон: вьюпорт = область между
   шапкой и низом экрана). Запас прокрутки под клавиатуру — `.windowInsetsPadding(WindowInsets.ime)`
   ВНУТРИ скролла, маржа докрутки 24.

## Документы на экране «Новый арендатор» (2026-09-27, решение Дениса)

Шит «Прикрепить документ» на создании был **заглушкой** (лончеры с пустыми колбэками `{ }`) —
файл никуда не сохранялся, и кнопка «Сохранить» от него не активировалась (ломался пример Вики
3695:33426 «начал заполнение с загрузки паспорта — кнопка стала активной»). Сделано по канону
редактирования (шит 2983:42346 + строка 2983:42232):

- лаунчеры (камера/галерея/файл) живут **на уровне экрана**, а не внутри шита — шит закрывается
  сразу после запуска интента, и объявленный в нём лаунчер размонтировался бы вместе с диалогом;
  имя камеры — «Фото от DD.MM.YYYY», имя из пикера — `docDisplayName`, имя в хранилище —
  `docStorageName` (общий хелпер в `DocumentParts.kt`);
- выбранный файл уходит в **стейдж** (`StagedDocument` — тот же тип, что в редактировании):
  строка документа видна сразу, `DocumentRow` (превью 40×40 r8 `#EFEFEF` + имя 15/600 +
  подпись 13/400 «JPG · добавлен DD.MM.YYYY»), корзина **убирает из стейджа** без диалога,
  тап открывает локальный `content://` (правило ACTION_VIEW из `DocumentParts.kt`);
- «Сохранить» активна от любого ввода **или прикреплённого файла**; диалог выхода 3695:33428
  тоже учитывает стейдж (иначе файл терялся бы молча);
- на сервер файлы уходят **после создания** арендатора: `POST /tenants` → `id` из ответа →
  `POST /upload?folder=documents` → `POST /tenants/:id/documents`. Если арендатор создан, а
  документы не прикрепились — тост «Арендатор сохранён, но документы не прикрепились»,
  созданное не теряем, файлы можно догрузить в карточке/редактировании.

## Брони, баяны и иконки (решения 2026-10-01)

- **Пересечение броней по ОБЪЕКТУ разрешено**: гость выезжает до 12:00, новый заезжает после 14:00 — так
  работают отели и посуточные, помесячные тоже меняют арендатора в один день.
- **Запрещено только одно**: две брони ОДНОГО арендатора на одном объекте на одинаковые даты
  (сервер отвечает 409). «Съехал и в тот же день заехал» — можно: конец
  первой = началу второй (пример: 22.09–21.11 и 21.11–23.12) — такие брони встык не пересекаются.
- **Правка брони НЕ должна терять арендатора**: `PUT /bookings/{id}` обновляет `tenant_id`
  только если поле пришло; клиент шлёт его явно (`CreateBookingRequest.tenantId`). Иначе
  привязка затиралась и в карточке объекта пропадала аватарка арендатора.
- **Карточка арендатора видит только СВОИ объекты**: брони, сделанные арендатором
  у других владельцев, в кабинет не попадают.
- **Баяны без анимации нажатия**: везде в проекте аккордеоны/баяны раскрываются
  БЕЗ ripple: `.clickable(interactionSource = remember { MutableInteractionSource() }, indication = null)`.
  Эталон — инфо-баян и история в карточке арендатора (`TenantCardScreen`).
- **Иконка звонка в кнопке «Позвонить» — КОНТУРНАЯ**: `ic_tab_call` (Figma `UI Icons / 21`, 17×17 обводкой,
  кадр `3801:67829`). Сплошная `ic_call_phone` остаётся только у иконок-подписей полей «Номер телефона».
